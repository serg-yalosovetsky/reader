# Стенды хрома читалки

Замеры интерфейса читалки на реальном `frontend/index.html` в headless Chrome.
Лежат в репозитории намеренно: ими доказаны тач-цели и жесты в serg/tasks#403,
и следующая приёмка должна иметь возможность прогнать их сама, а не собирать
свои с нуля.

## Запуск

```sh
cd .probe && npm install          # puppeteer-core, локальный Chrome не качается
node measure.mjs ../frontend      # геометрия хрома и размеры тач-целей
node behave.mjs  ../frontend      # поведение: заголовок, меню, жесты, a11y
```

Путь к Chrome берётся из `CHROME_PATH`, по умолчанию —
`C:/Program Files/Google/Chrome/Application/chrome.exe`.

`measure.mjs` завершается ненулевым кодом, если хоть одна цель меньше 44 px.

## Чем меряются тач-цели и почему именно так

Хит-тестом (`document.elementFromPoint` по обеим осям от центра элемента), а
НЕ геометрией бокса и не размером псевдоэлемента.

Это не педантизм: расхождение между двумя способами однажды дало в отчёте
«44 px» при фактических 34 px под пальцем. Невидимый `::before` со свесом
наружу был нарисован правильных размеров, но обрезался `overflow:hidden`
родителя и перекрывался соседним слоем. Бокс отвечает на вопрос «нарисован
ли элемент», хит-тест — «можно ли по нему попасть»; проверять надо второе.

## Проверка стенда на слепоту

Стенд, который зелёный и до, и после правки, ничего не доказывает. Оба стенда
проверялись так:

- `measure.mjs` на коммите `2594820` (до починки тач-целей) выдаёт 34 / 26 / 39
  вместо 44 — то есть дефект он видит;
- `behave.mjs`: со снятой проверкой `getSelection()` двойной тап при активном
  выделении включает полный экран (2 вызова вместо 1).

Делайте так же с каждой новой проверкой: сначала убедитесь, что она падает без
исправления.
