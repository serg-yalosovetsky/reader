# Spec: идентичность книги и устранение дублей-тёзок

Статус: в работе (SDD). Владелец: Серж.

## 1. Проблема
`monitor.check_all()` для каждой ficbook/fanfics-книги ищет «зеркало» на
author.today через `authortoday.search_work(title, author)`, который матчит
преимущественно по НАЗВАНИЮ (TITLE_MIN=0.80) и игнорирует автора при
`title_s>=0.95`. Найденная КНИГА-ТЁЗКА другого автора:
- скачивается как новый `Work` (site=authortoday) — `_find_existing` не находит
  совпадения, т.к. автор другой;
- отдаёт свою обложку → «некорректная обложка»;
- перецепляет монитор ficbook-книги на себя (`mon.work_id = new.id`).

Итог: в библиотеке по 3-5 «Собачья жизнь»/«Оракул»/«Из тьмы» разных авторов,
хотя у пользователя по одной с ficbook.

## 2. Правило идентичности
Книга та же самая, если совпадает произведение — НЕ по строгому «автор+название»
(автор на разных ресурсах записан ником или настоящим именем; ник на разных
сайтах отличается, т.к. занят). Нужна функция, устойчивая к вариациям автора.

## 3. Функция `same_book(a, b, *, get_text_a=None, get_text_b=None) -> bool`
Модуль `backend/app/book_identity.py`. Дескриптор: {title, author, series,
annotation, chapters, words}.

1. Ворота по названию: `title_sim >= 0.90` (нормализация + выравнивание «том N/#N»),
   иначе разные.
2. `author_relation -> MATCH|CONFLICT|UNKNOWN`:
   равны | один ник ⊂ другого | общий токен-слово | ratio>=0.85 | транслит кир<->лат
   => MATCH; пусто => UNKNOWN; иначе CONFLICT.
3. Решение:
   - author==MATCH и серия не конфликтует => та же;
   - иначе (ник vs имя): annotation_sim>=0.75 => та же;
     series==MATCH и annotation_sim>=0.5 => та же;
   - author==CONFLICT и аннотаций нет/непохожи: при наличии текста — отпечаток
     (первые ~3000 симв + заголовки глав, ratio>=0.9); иначе разные;
   - неоднозначно => консервативно РАЗНЫЕ.

Политика: одного названия НЕ достаточно — нужна опора (автор | аннотация |
серия | текст).

## 4. Точки интеграции
1. monitor._check_at_source — верификация зеркала перед скачиванием (главный фикс).
2. services._find_existing — дедуп через same_book (ник vs имя сливаются).
3. library._dedup_works — кластеризация через same_book.
4. covers._mirror_urls — проверять same_book перед обложкой.
5. authortoday.search_work — убрать лазейку title>=0.95, отдавать кандидатов.
