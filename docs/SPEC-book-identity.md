# Спецификация: идентичность книги, дедуп и антидубли в reader.ibotz.fun

Статус: **действует** (реализовано и в проде). Версия 3 · 2026-07-12.
Метод: Spec-Driven Development — **этот документ обновляется при каждом изменении
поведения**; код должен соответствовать спеке, а не наоборот.

Владелец: Серж. Репозитории: `github.com/serg-yalosovetsky/reader` (origin) +
`forgejo.ibotz.fun/serg/reader` (forgejo, приватный). Ветка `main`.

## 0. Контекст сервиса

Личная веб-читалка фанфиков/книг. FastAPI + uvicorn (1 воркер), systemd-юнит
`reader.service`, `WorkingDirectory=/root/reader`, порт `127.0.0.1:8123`, за
nginx `reader.ibotz.fun`. Фронтенд — статические ES-модули (`/root/reader/frontend`,
без сборки), отдаются `StaticFiles`.

**Боевая БД — Postgres (mesh-postgres)** через `READER_DB_URL=
postgresql+psycopg://reader:***@127.0.0.1:5433/reader`. Переменная задана ТОЛЬКО
в окружении systemd-юнита. SQLite `/root/reader/data/reader.db` — устаревший
dev-файл, НЕ используется в бою.
> ⚠️ Любой standalone-скрипт/миграция ОБЯЗАН экспортировать `READER_DB_URL`, иначе
> тихо подключится к устаревшему SQLite (там нет новых колонок → падение/порча).

Источники книг (`Work.site`): `ficbook`, `fanfics`, `authortoday`, `ao3`, `ffn`,
`searchfloor`, `readli`, `calibre`, `upload`, `drive-books`.

## 1. Проблема, которую решает спека

Монитор обновлений для каждой отслеживаемой книги ищет «более полное зеркало» на
author.today (AT — быстрый рус.источник с посимвольным API). Исходный поиск
(`authortoday.search_work`) матчит **преимущественно по названию**. Из-за этого:

1. **Импорт книг-тёзок.** Книга другого автора с тем же названием («Собачья жизнь»,
   «Оракул», «Из тьмы» — десятки разных авторов) считалась «зеркалом», скачивалась
   как **новый `Work`** (у `_find_existing` не совпадал автор), тащила чужую обложку
   и **перецепляла монитор** ficbook-книги на себя (`mon.work_id = new.id`).
2. **Ложные не-дубли и ложные дубли** при наивном сравнении `(автор, название)`:
   один и тот же автор на разных ресурсах записан **ником или настоящим именем**;
   ник на другом сайте бывает занят → берётся другой ник. Строгое равенство и
   плодит карточки одной книги, и путает разные книги-тёзки.

**Правило (Серж):** книга та же самая, если это то же ПРОИЗВЕДЕНИЕ. Определять
устойчиво к вариациям автора; при недостатке сигналов — **сверять по тексту**.

## 2. Модуль идентичности `backend/app/book_identity.py`

Чистый модуль (без БД/сети; чтение файла-книги допускается в `extract_text_sample`).
Дескриптор книги — dict; любое поле опционально:
`{title, author, series, series_index, annotation, chapters, words, file_path, file_format}`.

### 2.1 Публичный API
- `same_book(a, b, *, get_text_a=None, get_text_b=None, title_gate=0.90, ann_strong=0.75, ann_medium=0.50) -> bool`
- `author_relation(a, b) -> "match"|"conflict"|"unknown"`
- `annotation_sim(a, b) -> float | None`
- `series_relation(a, b) -> (rel, idx_conflict)`
- `title_sim(a, b) -> float`
- `extract_text_sample(path, fmt="", max_chars=4000) -> str`
- `work_descriptor(orm_work) -> dict` (включая `file_path`/`file_format`)

### 2.2 Нормализация
- `_norm(s)`: lower, снять кавычки `"“”«»'` + бэктики, пунктуация → пробел (unicode
  `\w`), схлопнуть пробелы.
- `_title_key(s) -> (base, num|None)`: снять хвост тома (`том|тома|томах|книга|книги|
  часть|части|part|book|vol|volume` + число) ИЛИ завершающее число; вернуть базовое
  название и номер тома. Только многобуквенные маркеры (одиночные буквы не трогаем).
- `_tokens(s)`: слова длиной ≥3.
- Транслит лат→кир (`_lat2cyr`): грубая фонетическая карта (shch/zh/ch/…, a→а…);
  для «Brandon»↔«Брендон».

### 2.3 Сигналы

**author_relation(a,b):**
| условие | результат |
|---|---|
| один из пуст | UNKNOWN |
| равны после `_norm` | MATCH |
| один как отдельное слово входит в другой (`\bnick\b`) — «Имя "ник"» | MATCH |
| пересечение токенов ≥3 симв. (общая фамилия/ник) | MATCH |
| `SequenceMatcher.ratio ≥ 0.85` (опечатка/огласовка: «Уилан»/«Уилэн») | MATCH |
| транслит-совпадение (ratio≥0.82 или общий токен ≥4) | MATCH |
| иначе | CONFLICT |

**annotation_sim(a,b):** обе аннотации `_norm`; если любая < 40 симв. → `None`
(сигнала нет). Иначе `max(ratio(a[:1500], b[:1500]), tokenJaccard)`.

**series_relation(a,b):** серии `_norm`; равны / `ratio≥0.9` / общий токен → MATCH;
одна пуста → UNKNOWN; иначе CONFLICT. `idx_conflict = MATCH и оба series_index заданы
и различны` (том 1 ≠ том 3 одной серии).

**_text_fingerprint(ta,tb, thresh=0.85):** оба `_norm`, обрезка до 3000 симв.; если
любой < 500 → False; иначе `ratio ≥ 0.85`.

### 2.4 Алгоритм `same_book` (порядок = приоритет сигнала)
1. **Ворота по названию:** `title_sim(base_a, base_b) < title_gate(0.90)` → `False`.
2. **Разные тома:** если хоть у одного есть номер тома и `(na_num or 1) != (nb_num or 1)`
   → `False` («Оракул» = том 1 ⇒ ≠ «Оракул 2»).
3. **Автор совпал** (`MATCH`): `return series_relation != CONFLICT`.
4. **Аннотации совпали сильно** (`ann ≥ 0.75`) → `True` (закрывает ник vs имя).
5. **Серия совпала + аннотации средне** (`ser==MATCH и ann ≥ 0.5`) → `True`.
6. **Аннотаций нет/слабые** (`ann is None или < 0.5`) **и даны текст-геттеры** →
   `_text_fingerprint(get_text_a(), get_text_b())` → `True` при совпадении.
   Работает и при `CONFLICT`, и при `UNKNOWN` авторе.
7. Иначе → `False` (консервативно: непроверенное считаем разными книгами).

**Политика:** одного совпадения названия НЕ достаточно — нужна положительная опора
(автор ∨ аннотация ∨ серия ∨ текст). Геттеры ленивы: сеть/чтение файла происходит
только когда алгоритм дошёл до шага 6.

### 2.5 Извлечение текста
- `extract_text_sample(path, fmt)` — первые ~4000 симв. текста: fb2 (`<body>` без
  тегов) или epub (склейка xhtml/html до 3× лимита, снятие тегов). `''` при ошибке.
- `authortoday.fetch_text_sample(url)` — первая глава AT (reader-страница →
  `_parse_chapters` → `_fetch_chapter`, аноним). `''` при неудаче/платной главе.

## 3. Данные: модель `Work` (`backend/app/db/models.py`)

Ключевые поля: `id, title, author, site, source_url, file_path, file_format, sha1,
calibre_id, chapters_count, cover_path, cover_source, cover_brief, description
(=аннотация), genres, characters, fandom, rating, status, words, meta_synced,`
**`series` (str), `series_index` (int, номер книги в цикле)**`, created_at, updated_at`.

Авто-миграция (`db/session._migrate_add_columns`) досоздаёт новые колонки через
`ALTER TABLE` при старте — отдельные миграции не нужны.

**Источники серии/номера** (заполняются при импорте и бэкфилле `backfill-meta`):
- fb2: `<sequence name="…" number="N">`
- epub: `calibre:series` / `calibre:series_index` (или `belongs-to-collection`)
- author.today: ссылка `/work/series/<id>` (+ `#N` рядом)
Проброс адаптер→Work: `DownloadResult.extra` → `services._apply_file` (мёрж ключей
`genres,rating,status,characters,fandom,words,series,series_index`).

Смежные модели: `Monitored(source_url, work_id, has_update, last_seen_chapters,
last_checked)`, `Progress(work_id, ratio, locator, text_anchor, last_read_time,
source)`, `Blacklist(title_norm, author_norm, source_url)`.

## 4. Конвейер монитора и точки интеграции `same_book`

`accounts/monitor.check_all(pull_feeds, auto_download, only_pending)`:
1. **Фиды подписок** (`feeds.pull_all`): ficbook/authortoday/fanfics → `add_monitor`.
2. **Фаза 1 (read-only):** на каждую отслеживаемую книгу — счёт глав (ficbook через
   FanFicFare+cloudscraper, последовательно) и **поиск AT-зеркала** (`_at_task` →
   `_check_at_source`, пул 5 httpx).
3. **Фаза 2:** выбрать источник с бóльшим числом глав; если это верифицированное
   AT-зеркало и глав больше — `_download_and_write` → `register_download` (дедуп) →
   `mon.work_id = work.id`. Транзакция открыта только на запись (< 1 c).

### Пять точек, где применяется `same_book`
1. **`monitor._check_at_source(our)`** — ГЛАВНАЯ защита. После `search_work` тянет
   `fetch_meta(at_url)` и прогоняет `same_book(our, at_meta, get_text_a=<локальный
   файл>, get_text_b=<первая глава AT>)`. Не совпало → зеркало игнорируется. Без этого
   тянулась чужая книга-тёзка.
2. **`services._find_existing(result)`** — дедуп при регистрации скачанного: строит
   дескриптор из `result` (+ `annotation`/`series` из `extra`), сверяет `same_book`
   со всеми `Work` (текст скачанного файла — один раз, ленивая мемоизация; текст
   кандидата — из его файла). Совпало → возвращает существующий Work (мёрж), иначе
   создаёт новый.
3. **`library._dedup_works`** (кнопка «Обслуживание» / `POST /api/library/maintenance`)
   — кластеризация по базовому названию → `same_book` внутри (с текст-геттерами).
   **Правило безопасности:** кластер с `upload`+пустой автор НЕ сливаем (сборники/
   омнибусы/трилогии без автора ≠ одиночная книга-тёзка).
4. **`covers._mirror_urls`** — обложку с AT-зеркала берём только если `same_book`
   подтвердил ту же книгу.
5. **`authortoday.search_work`** — сырой кандидат по названию+автору; убрана лазейка
   «title≥0.95 ⇒ игнор автора»; финальную идентичность решают вызывающие через
   `same_book`.

### Инвариант антидубля (критично)
`_check_at_source` верифицирует зеркало **в т.ч. по аннотации/тексту**. Чтобы
`_find_existing` при регистрации пришёл к тому же вердикту, **аннотация обязана
попасть в `DownloadResult.extra`** (`authortoday.download()` кладёт `annotation`).
Иначе `same_book` при регистрации не находит совпадения и зеркало той же книги
создаётся как новый Work — дубль возвращается после КАЖДОЙ плановой проверки
(инцидент «Нагльфар»: #71 Морроу Винд + рецидивный #1506 Кузьмин Марк, аннотации
идентичны). Для любого downloader, чей результат может совпасть с существующей
книгой не по `source_url`, аннотация в `extra` — часть контракта.

## 5. Вторая проблема: плашка «обновление» и «прочитано»

Симптом: пришла новая глава (128→129), но карточка «прочитано» и без плашки.

Фронт (`library.js.bookCard`): `done = ratio ≥ 0.98`; `showUpdate = hasUpdate && !done`
(дочитанную книгу не мигаем ложной плашкой от активности автора). Предполагалось, что
новая глава сама уронит `ratio`. Но скачивание главы **не трогает** сохранённый
`Progress.ratio` — дочитанная книга остаётся ~0.9999 ⇒ `done` ⇒ плашка подавлена.

**Фикс `services._unfinish_progress(session, work_id, old_len, new_len)`:** при замене
файла более полным (текст вырос) масштабируем `ratio *= old_len/new_len`; если из-за
малого прироста остаётся `≥ 0.98` — опускаем до `0.97`. Книга перестаёт числиться
прочитанной, плашка возвращается. Позиция чтения не теряется (`locator`/`text_anchor`).

## 6. Фронтенд: фильтр по автору/серии

Клик по автору или серии фильтрует библиотеку. Реализовано в трёх местах, каждое
зовёт `filterBy(value)` (кладёт значение в `#lib-filter`, рендерит через
`applyLibFilter`, который матчит `title|author|series`):
- карточка: `.b-author` (кликабелен), строка `.b-series` «📚 Серия #N»;
- hover-панель превью (десктоп, перекрывает карточку): `.lh-author`/`.lh-series`;
- страница книги: `.bp-author` (внешняя ссылка автора осталась кнопкой «↗ Оригинал»),
  `.bp-series`; клик возвращает в библиотеку (`goFilter`) и фильтрует.
`loadLibrary` **сохраняет** активный фильтр из `#lib-filter` (иначе возврат со
страницы книги `popstate→loadLibrary→applyLibFilter('')` сбрасывал его). Сброс —
очистить поле фильтра.

## 7. Пороги (сводка)
| параметр | значение | где |
|---|---|---|
| `title_gate` | 0.90 | ворота названия |
| author ratio | 0.85 | опечатка/огласовка |
| translit ratio | 0.82 | лат↔кир |
| `ann_strong` | 0.75 | аннотации ⇒ та же |
| `ann_medium` | 0.50 | аннотации + серия ⇒ та же; ниже — текст |
| annotation min len | 40 символов | иначе сигнала нет |
| text fingerprint | 0.85 | сверка текста |
| text min len | 500 символов | иначе не сверяем |
| text sample | 4000 символов | размер выборки |
| read threshold | 0.98 | `ratio` ⇒ «прочитано» |
